# 技术说明与安全边界

服主不需要理解密码学即可部署和使用；安装、换机和审批步骤见 [README](../README.md)。本文用于说明实现细节和适用边界。

## 设备与恢复凭据

- 使用 Ed25519 设备密钥签署每次登录挑战，服务端保存公钥，设备私钥不通过认证协议发送给服务端。
- 每个服务器与玩家拥有独立恢复密钥，用于登记新设备、管理已登记设备和轮换恢复凭据。恢复备份包含私钥，拿到有效备份的人能够登记新设备。
- Windows 使用当前系统用户的 DPAPI 保护安装密钥，设备和恢复私钥使用 AES-GCM 加密存储。Linux / macOS 不提供相同的 DPAPI 保护，依赖本地安装密钥、文件权限和本机绑定校验。
- 本机绑定用于减少整合包或数据目录复制后直接复用身份的风险，不等同于 TPM 或安全芯片级不可导出密钥。
- 同一系统账户上的多个启动器实例共享存储。同一电脑不同游戏目录不是独立的凭据隔离边界。

## 登录与账户修改

- 登录验证在 Forge 登录协商阶段完成，验证失败的连接不能进入世界。
- 登录签名绑定会话、随机数、服务器、玩家、认证方式及设备信息；挑战短期有效且一次性消费。
- 设备管理和恢复轮换需要恢复密钥授权，并绑定一次性随机数、签发时间和账户修订号。
- 已建立恢复身份的账户，撤销最后一台设备也不会退回首台设备自动登记状态。
- 首次建立全新玩家记录时自动接受首台设备，不能阻止用户名抢注。白名单或其他注册策略仍由服主负责。

## 存储、接口与性能

- 服务器玩家 JSON 和主要验签工作不在 Netty 网络线程执行。认证工作使用 1–2 个后台线程和有界 128 项队列，玩家账户操作使用各自的锁。
- 客户端在登录和账户操作时读取凭据，不持续进行设备指纹扫描；可选的原版文件校验功能有自己的扫描行为。
- 内置审批接口只提供 HTTP。公网访问需要可信 HTTPS 入口和对原始端口的访问限制；完整审批链接应按管理凭据保护。
- 获得玩家正在使用的系统账户权限、有效恢复私钥或服务器玩家数据管理权限的人，仍可能冒充或重新登记玩家。

## 验证范围

自动测试目前只覆盖服务器许可证的 JSON 往返读写与忽略旧二进制许可证。它们不能替代设备认证、恢复和审批的完整联机回归。

两个历史文件校验 Mixin 使用固定方法映射；目前编译器会给出目标方法检查警告，需要在实际客户端和服务端启动中验证。不要仅凭构建成功声明完整运行兼容性。
