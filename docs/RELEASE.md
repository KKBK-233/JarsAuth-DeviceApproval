# 发行与联机验收

目标环境：Minecraft `1.20.1`、Forge `47.4.13`、Java `17`，客户端和独立服务端使用完全相同的发行 JAR。

## 构建包

执行 `gradlew clean build --no-daemon`，再执行 `python scripts/prepare_release.py`，从 `build/libs/` 获取 JAR 和 `SHA256SUMS`。摘要便于服主确认客户端与服务端使用同一个文件。

[构建检查](https://github.com/KKBK-233/JarsAuth-DeviceApproval/actions/workflows/build.yml) 在 Windows 和 Linux 上使用 Java 17 编译、运行现有测试、检查 JAR 元数据并生成摘要。构建成功后，JAR、摘要和测试报告保存在该次运行的附件中，保留 14 天。

自动构建只证明编译、打包及现有许可证测试通过，不会自动发布稳定版或社区项目。

## 稳定版发布前的实际验收

| 场景 | 通过条件 |
| --- | --- |
| 首次安装 | 确认默认关闭，按 README 启用后产生正确配置与数据 |
| 首台设备 | 白名单玩家首次登记成功，生成正确作用域的恢复备份 |
| 已登记设备 | 断开并重连，进入世界前验证通过，无需游戏内输入密码 |
| 未批准设备 | 使用同名玩家从独立设备连接，被拒绝并产生待审批记录 |
| 管理员审批 | 命令与受保护网页都能批准 / 拒绝请求，批准后重连成功 |
| 换机恢复 | 新设备导入有效备份可登记；放错服务器或玩家的备份被拒绝 |
| 设备撤销 | 撤销后该设备下一次登录被拒绝，不把账户退回首台自动登记 |
| 恢复轮换 | 新备份可用于登记，旧备份失效 |
| 重启恢复 | 已批准设备和待审批数据能恢复，过期请求不可使用 |
| 历史功能 | 客户端和服务端无 Mixin 启动失败，可选文件校验 / 许可证功能按启用状态工作 |

记录每项的实际环境、结果与日志位置；未完成的项目不能填写为已通过。跨操作系统支持需要分别记录客户端与服务端的运行组合。
